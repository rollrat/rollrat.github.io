## 개발자가 AI 길들이는 데 6개월 걸린 이유 (시행착오 전부 공개)
> 📅 2026-02-21 | ⏱️ 14분 | [영상 링크](https://www.youtube.com/watch?v=7vihh_G_434)

### 핵심 요약
- AI를 그냥 쓰면 50점짜리지만, 4가지 시스템(자동 매뉴얼, 작업 기억, 자동 품질 검사, 전문 에이전트)을 구축하면 95점까지 끌어올릴 수 있다.
- AI의 핵심 문제는 두 가지: 매뉴얼을 스스로 안 읽는 것과 30분마다 맥락을 잃어버리는 금붕어 기억력이다.
- 훅(Hook) 기능을 활용한 자동 알림 장치로 AI가 작업 전 관련 매뉴얼을 강제로 참조하게 만들 수 있다.
- 계획서, 맥락 노트, 체크리스트 3가지 문서를 통해 AI가 아무리 긴 대화에서도 목표를 잃지 않도록 한다.
- 이 영상의 내용은 Reddit에 올라온 한 개발자의 실제 6개월 사용 경험을 정리한 것으로, Claude Code뿐 아니라 모든 AI 도구에 적용 가능하다.

### 주요 내용

#### 0:00 - 인트로
8년차 개발자가 회사 내부 프로그램(8년 된 레거시)을 혼자서 처음부터 재개발하는 프로젝트를 맡았다. Claude Code를 활용해 6개월 만에 원래의 3~4배 규모(책 300~400권 분량)를 완성했다. 성공 비결은 AI에게 일을 맡기는 것이 아니라, AI가 잘 일하도록 시스템을 구축한 것이다.

#### 1:15 - AI의 문제점
AI의 3가지 고질적 문제:
1. 30분마다 작업 맥락을 잊어버림 (금붕어 기억력)
2. 매뉴얼이 바로 옆에 있어도 스스로 펴 보지 않음
3. "다 했습니다"라고 자신감 넘치게 말하지만 실수가 수두룩함

#### 3:43 - 시스템 1: AI 자동 매뉴얼

**문제:** 클로드 코드의 스킬(Skill) 기능으로 수천 줄의 업무 가이드라인을 만들었지만 AI가 아예 안 읽음.

**해결책 - 훅(Hook) 기능 활용:**
- 시작 전 알림 장치: AI가 지시를 받기 전, 지시 내용을 분석해 관련 매뉴얼 챕터를 자동으로 알려줌
- 완료 후 체크 장치: AI가 작업을 마치면 자동으로 에러 처리, 보안 등을 상기시켜줌

**자동 매칭 규칙 4가지:**
- 키워드 감지 (예: "API", "백엔드" → 백엔드 매뉴얼 활성화)
- 작업 유형 감지 (예: "추가해 줘", "새로운 기능" → 해당 영역 매뉴얼)
- 작업 위치 감지 (특정 폴더 수정 시 관련 매뉴얼 자동 활성화)
- 파일 내용 감지 (파일 내 특정 패턴 존재 시 관련 매뉴얼 활성화)

**최적화:** 1,500줄짜리 매뉴얼을 목차 + 상세 챕터 파일로 분리 → AI 자원 소비 40~60% 절감

#### 9:11 - 시스템 2: AI 작업 기억

**문제:** 대화가 길어지면 AI가 처음 세운 계획에서 이탈함.

**해결책 - 3가지 문서 시스템:**
- 계획서: 무엇을 만들 건지 처음부터 끝까지 기술 (설계도)
- 맥락 노트: 왜 이런 결정을 했는지, 관련 자료 위치 (시방서)
- 할 일 체크리스트: 완료 항목과 남은 항목 추적 (공정표)

**운용 방법:**
1. AI에게 계획을 먼저 세우게 한다
2. 계획을 꼼꼼히 검토해 오해 여부를 확인한다
3. 계획 승인 직후 문서로 저장시킨다 (AI가 바로 달려드는 것을 막음)
4. 새 대화를 시작할 때 저장된 문서를 읽고 이어서 작업하게 한다
5. 한 번에 1~2개 작업만 시키고 완료 후 체크리스트를 업데이트시킨다

#### 12:25 - 시스템 3: 자동 품질 검사

- 수정 기록 장치: AI가 파일을 수정할 때마다 CCTV처럼 자동 기록
- 완료 후 검사 장치: 작업이 완전히 끝난 시점에만 오류 자동 검사 (중간 검사는 비효율적)
- 오류가 적으면 AI가 바로 수정, 오류가 많으면 전문 수리 담당 추천
- 셀프 체크 리마인더: 작업 완료 후 에러 처리, 보안 등 확인 항목을 자동으로 상기시킴

#### 13:14 - 시스템 4: 전문 AI 팀원 + 마무리

- 역할별 전문 에이전트 배치: 품질 관리팀, 테스트팀, 기획팀 등
- AI 팀원에게 "다 했습니다"가 아닌 발견 사항, 수정 내용, 판단 근거를 보고서로 제출하도록 지시
- 코드 리뷰 에이전트: 다른 AI 팀원이 결과물을 검토해 누락, 취약점, 일관성 문제 포착
- 이 모든 시스템은 Reddit의 실제 개발자 사례를 정리한 것으로, 특정 도구에 국한되지 않음

### Q&A

**Q1. Claude Code가 없어도 이 시스템을 적용할 수 있나요?**
영상에서 명시적으로 "ChatGPT를 쓰든 Gemini를 쓰든 어떤 AI 도구를 쓰든 마찬가지"라고 밝히고 있다. 핵심 원리인 사전 맥락 제공, 문서 기반 기억 보완, 단계적 작업 분리는 도구에 무관하게 적용 가능하다. 다만 훅(Hook)이나 스킬(Skill) 같은 자동화 기능은 Claude Code 고유의 기능이므로, 다른 도구에서는 수동으로 프롬프트를 통해 유사한 효과를 구현해야 한다.

**Q2. 매뉴얼(스킬)은 어떻게 작성하면 되나요?**
작업 영역별(프론트엔드, 백엔드, 데이터베이스 등)로 구분해 각 영역의 코딩 규칙, 금지 패턴, 에러 처리 방식 등을 정리한다. 영상에서 강조한 핵심 교훈은 처음부터 너무 길게 만들지 말라는 것이다. 1,500줄짜리 단일 문서보다 간략한 목차와 세분화된 챕터 파일로 나누는 구조가 AI 자원 소비를 40~60% 줄이고 실제 활용도도 높다.

**Q3. AI가 계획에서 이탈하지 않으려면 가장 중요한 것이 무엇인가요?**
영상은 "계획은 왕"이라고 강조하며, 작업 시작 전 AI가 직접 계획을 수립하게 하고 사람이 꼼꼼히 검토하는 과정이 핵심이라고 설명한다. 계획 승인 직후 문서화(계획서, 맥락 노트, 체크리스트)를 먼저 완료한 뒤 새 대화에서 해당 문서를 읽고 시작하는 방식이 기억 손실을 방지하는 가장 효과적인 방법이다. 또한 한 번에 전체를 시키지 않고 1~2개 단위로 나눠 완료를 확인하는 것도 이탈 방지에 중요하다.
