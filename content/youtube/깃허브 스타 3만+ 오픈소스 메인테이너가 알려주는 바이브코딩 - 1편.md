## 깃허브 스타 3만+ 오픈소스 메인테이너가 알려주는 바이브코딩 - 1편

### 핵심 요약
- **Codex 기반 병렬 개발 워크플로우**: GitHub 이슈를 AI로 자동 생성하고, 여러 Codex 인스턴스를 동시에 돌려 복수 이슈를 병렬 처리한다.
- **플랜 모드(Flat Mode) 활용**: Codex의 플랜 모드를 적극 활용해 AI가 상세 계획을 수립하게 하고, 사람은 계획 검토·승인에만 집중한다.
- **문서 주도 개발(Doc-driven)**: docs/ 폴더를 "소스 오브 트루스"로 삼고 AGENTS.md에서 참조시켜 토큰 낭비 없이 AI가 전체 구조를 파악하게 한다.
- **워크트리(Worktree) 전략**: 여러 기능을 동시 개발할 때 git worktree를 사용해 리베이스 충돌을 최소화한다.
- **진짜 개발자의 역할**: AI가 만든 "눈속임 코드" 조각들을 조립·디버깅해 실제 작동하는 프로젝트를 완성하는 능력이 AI 시대 개발자의 핵심 역량이다.

### 주요 내용

#### 1. AI 이슈 생성 → 병렬 Codex 처리
스트리머(삶은코딩)는 Rust 기반 오픈소스 monorepo(SWC 관련 프로젝트들)를 개발한다. 먼저 Claude/Codex에게 cargo mono, node-up, MPF 등 프로젝트의 이슈를 자동으로 찾아 GitHub에 등록시킨다. 이슈는 AI가 상세하게 작성하기 때문에 품질이 높고, 이슈 목록이 완성되면 여러 Codex 인스턴스를 동시에 띄워 각 이슈를 병렬로 처리한다. 이를 통해 사람이 병목이 되는 상황을 최소화한다.

#### 2. Codex vs Claude Code 비교
Codex는 지시사항을 정확히 따르는 대신 AGENTS.md 등 지시 파일이 잘 작성되어 있어야 제대로 작동한다. Claude Code는 지시를 어느 정도 "눈치껏" 처리하지만 지시를 무시하는 경향이 있다. 발표자는 Codex를 주로 사용하며, Claude Code는 코드 리뷰(GitHub Actions 연동)에 활용한다. Copilot 리뷰는 신뢰도가 낮아 거의 쓰지 않는다.

#### 3. 플랜 모드(Flat Mode) 사용법
Codex의 플랜 모드는 단축키 `Cmd+Shift+P`로 진입하며, AI가 먼저 상세 계획을 제시하고 사람이 승인·조정한다. 계획을 직접 수정하면 플랜이 망가질 수 있으므로 "모르면 설명해 달라"고 요청하는 것이 낫다. 계획의 모든 내용을 다 읽을 필요는 없고, 첫 흐름과 선택지만 파악해도 충분하다.

#### 4. 문서 주도 개발 & AGENTS.md 전략
docs/ 폴더에 각 프로젝트(cargo mono, node-up 등)의 명령어, 패키지 레이아웃, 설계 사항을 상세히 기록한다. AGENTS.md에서 이 docs를 "소스 오브 트루스"로 참조하게 지시한다. AI 에이전트는 코드 전체를 직접 읽는 대신 문서를 읽으므로 토큰 절약 + 이해 정확도 향상이 동시에 달성된다. 작업 완료 후에는 반드시 관련 문서를 업데이트하도록 지시한다.

#### 5. Rust 개발의 현실적 문제: 디스크 용량
cargo target 폴더가 프로젝트당 55~90GB를 차지하며, 클론 4개로 약 600GB를 소비했다. 이로 인해 OBS 화면이 자주 멈추는 문제가 발생했다. 이를 해결하기 위해 "Devmon"이라는 데몬 도구를 만들기 시작한다 — 등록된 폴더들을 주기적으로 git pull하고, 주기적으로 cargo clean 등 명령을 자동 실행하는 도구다.

#### 6. AGENTS.md vs MCP vs 스킬 비교
발표자는 MCP/스킬보다 AGENTS.md를 선호한다. MCP와 스킬은 툴콜링 기반인데, AI가 툴을 제대로 사용하려면 툴 당 수십 줄의 상세한 설명이 필요하다. 반면 AGENTS.md는 시스템 프롬프트에 바로 들어가므로 더 안정적으로 작동한다. 최근 Codex 사례에서도 스킬보다 AGENTS.md 방식이 성능이 높다고 검증됐다.

#### 7. AI 시대 개발자의 가치
"바이브 코더"는 AI가 만든 조각들을 조립하지 못하고, 눈속임 코드(로컬 상태로만 처리하는 코드 등)를 구분·디버깅하지 못한다. 반면 진짜 개발자는 조각들을 조립하고 통합 과정의 버그를 디버깅할 수 있다. 유닛 테스트보다 "기능이 작동하는지 먼저 확인 → 테스트로 리그레션 방지"라는 순서를 권장한다. 개발자 직무가 사라진다기보다 적어지며, 대체 주체도 AI가 아닌 "AI를 잘 쓰는 개발자"일 것이다.

### Q&A

**Q1. Codex와 Claude Code를 어떻게 구분해서 사용하나요?**
Codex는 AGENTS.md 지시를 충실히 따르는 성격이므로 "실제 코딩 작업"에 주로 사용한다. 지시가 명확하게 작성되어 있으면 Codex가 훨씬 강력하다. Claude Code는 지시를 어느 정도 무시하는 대신 눈치껏 해결하는 면이 있으며, GitHub Actions와 연동한 자동 코드 리뷰에 활용한다. 즉 "코드 작성은 Codex, 리뷰 자동화는 Claude Code"로 역할을 분리한다.

**Q2. 여러 이슈를 병렬 처리할 때 리베이스 충돌은 어떻게 방지하나요?**
git worktree를 사용하면 동일 저장소를 여러 작업 디렉터리로 분리할 수 있어 브랜치 간 충돌이 줄어든다. 또한 같은 파일을 건드리는 이슈끼리는 같은 프로젝트에서 동시에 잡지 않고 순차적으로 처리한다. 리베이스 충돌이 발생하면 처음부터 다시 시키는 방식을 택하기도 한다 — AI 작업은 재실행 비용이 낮기 때문이다.

**Q3. AGENTS.md와 docs/ 폴더 중심의 문서 주도 개발은 어떻게 시작하나요?**
먼저 프로젝트 루트에 docs/ 폴더를 만들고, 프로젝트별 명령어·패키지 구조·설계 결정을 Markdown으로 정리한다. AGENTS.md에서 "docs/를 소스 오브 트루스로 삼아라"고 명시하면 AI 에이전트가 코드 전체를 그렙하는 대신 docs를 먼저 참조한다. 매 작업이 끝나면 관련 문서를 업데이트하도록 프롬프트에 포함시키는 것이 핵심이다.
