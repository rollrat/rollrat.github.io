## RAG 어렵다고요? PDF 하나로 5분 만에 시작하는 법 (feat. 공원나연님)
> 📅 2026-02-23 | ⏱️ 37.8분 | [영상 링크](https://www.youtube.com/watch?v=AISuJHMCWog)

### 핵심 요약
- **Graph RAG vs Vector RAG**: 일반 RAG는 텍스트 청크를 단순 저장하지만, Graph RAG는 청크 간 관계를 그래프로 연결하여 풍부한 맥락을 포함한 답변 생성이 가능하다
- **그래프 DB의 강점**: 관계형 DB와 달리 데이터 간 관계를 엣지(화살표)로 직관적으로 저장해 JOIN 없이 빠른 탐색이 가능하다
- **온톨로지 설계의 중요성**: GraphRAG 구현의 핵심은 도메인 지식을 구조화한 그래프 스키마(온톨로지)를 먼저 설계하는 것이다
- **초보자 접근법**: arrows.app으로 그래프를 직접 그려보고, Neo4j GraphRAG 패키지로 PDF를 자동 지식 그래프로 변환할 수 있다
- **실무 적용**: 제조업 고장 이력 분석, 교육 분야 선행 개념 맵 구축, 뉴스 카테고리 검색 등 다양한 도메인에 적용 가능하다

### 주요 내용

#### 1. 그래프 데이터베이스란?
그래프 DB는 데이터 간의 관계를 화살표(엣지) 형태로 직관적으로 저장하는 데이터베이스다. 관계형 DB(RDB)에서는 테이블 간 JOIN이 필요하지만, 그래프 DB는 노드와 엣지를 따라가며 직관적으로 탐색한다. 예를 들어 "어떤 사람이 높은 평점을 준 액션 영화"를 질의할 때, 관계를 따라 바로 탐색이 가능하다.

#### 2. RAG의 개념과 내부 데이터의 중요성
RAG(Retrieval-Augmented Generation)는 질문에 답하기 전에 관련 정보를 먼저 검색하는 방식이다. 웹 검색과 달리, 내부 RAG는 조직만의 비공개 데이터를 기반으로 정확한 출처가 있는 신뢰도 높은 답변을 제공한다. 할루시네이션을 줄이고 근거 있는 답변이 가능하다.

#### 3. Vector RAG vs Graph RAG의 구조적 차이
Vector RAG는 문서를 청크로 잘라 벡터 DB에 저장하지만, 문맥이 끊긴 채로 저장된다. Graph RAG는 청크 노드 간의 관계를 그래프로 연결해 주변 맥락까지 함께 검색할 수 있다. 이를 통해 LLM이 계층적 구조와 문서 간 연관성을 파악해 품질 높은 답변을 생성한다. Obsidian의 그래프 뷰와 유사한 개념이다.

#### 4. 온톨로지 설계
온톨로지는 도메인의 암묵적 지식과 규칙을 AI가 이해할 수 있도록 구조화한 체계다. 교육 분야에서는 "2차 함수를 배우기 전에 방정식을 선행해야 한다"처럼 개념 간 선후 관계를 온톨로지로 표현해 AI가 적절한 추천을 할 수 있다. GraphRAG 구현을 위한 그래프 스키마 설계 과정과 본질적으로 동일하다.

#### 5. LangGraph 프레임워크
LangGraph는 AI 에이전트의 워크플로우를 그래프 형태로 설계하는 프레임워크다. 사용자 질문 → 의도 분석 → 정보 검색 → 답변 생성의 각 단계를 노드로 정의하고, 실행 순서를 그래프로 구성한다. LangGraph Studio를 통해 에이전트 흐름을 시각적으로 확인할 수 있다.

#### 6. GraphRAG 데모 및 실무 활용
정치 카테고리 뉴스 검색 데모: 질문을 하면 관련 기사 노드들이 그래프로 시각화되며, 어떤 근거로 답변했는지 눈으로 확인 가능하다. 제조 분야에서는 고장 설비 → 증상 → 원인 → 해결 방법을 그래프로 연결해 스마트 팩토리에 활용한다.

#### 7. 초보자를 위한 실전 가이드
1. **arrows.app**: Neo4j가 제공하는 무료 그래프 시각화 도구. 노드와 엣지를 드래그로 그려보며 그래프 사고를 연습
2. **Neo4j GraphRAG 패키지**: PDF 파일을 입력하면 자동으로 지식 그래프를 추출. 단 몇 줄의 코드로 문서를 그래프로 변환

#### 8. 패스트캠퍼스 GraphRAG 강의
공원나연님의 "GraphRAG의 모든 것" 강의 커리큘럼: Neo4j DB 사용법 → Cypher 쿼리 언어 → 그래프 모델링 → GraphRAG 구축 → 평가 방법 → 풀 데모 구현. 입문자부터 Vector RAG 경험자까지 대상. 조쉬 채널 구독자 할인 쿠폰 제공.

### Q&A

**Q1. Graph RAG는 Vector RAG보다 항상 더 좋은가요?**
반드시 그렇지는 않다. Graph RAG는 관계 중심의 복잡한 맥락이 필요한 질문에서 특히 강점을 발휘한다. 그러나 구축 비용(그래프 스키마 설계, 온톨로지 정의)이 더 높다. 단순한 문서 검색은 Vector RAG로도 충분하며, 조직 내 복잡한 관계 데이터(제조 로그, 교육 선행 학습, 법률 판례 연결 등)가 있을 때 Graph RAG가 진가를 발휘한다.

**Q2. 개발자가 아닌 비개발자도 GraphRAG를 시작할 수 있나요?**
충분히 가능하다. 첫 단계로 arrows.app에서 마우스 드래그만으로 자신의 데이터 구조를 그래프로 그려볼 수 있다. 이는 마인드맵이나 PM의 텍소노미 설계와 유사한 작업이다. 이후 Neo4j GraphRAG 패키지로 PDF를 자동 변환하면 코딩 없이도 그래프 구조를 확인할 수 있다. 다만 실제 에이전트 구축에는 Python 기초 지식이 필요하다.

**Q3. GraphRAG가 특히 효과적인 도메인은 어디인가요?**
관계 구조가 복잡하고 맥락이 중요한 도메인에서 효과적이다. 공원나연님이 언급한 사례로는 ① 제조업의 고장 이력 분석(설비-증상-원인-해결책 연결), ② 교육의 선행 개념 맵(2차 함수-방정식 선후 관계), ③ 뉴스 카테고리 검색(카테고리-기사-내용 청크 연결)이 있다. 조직 내 암묵지와 내부 문서가 많을수록 효과가 크다.
