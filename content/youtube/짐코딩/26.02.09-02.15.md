### 핵심 요약
- Pro 플랜에서 Opus 모델을 기본으로 사용하면 Sonnet 대비 4-5배 토큰 소진이 빨라져 2일 만에 주간 사용량의 80%가 소진될 수 있음
- AI는 매 요청마다 이전 대화 전체를 처음부터 끝까지 다시 읽기 때문에 컨텍스트 관리가 토큰 절약의 핵심
- settings.json에서 모델을 Sonnet으로 고정하고, opusplan 설정으로 설계는 Opus, 실행은 Sonnet으로 자동 전환 가능
- /clear, /compact, Extended Thinking 제어, 구체적 프롬프트 작성 등 6가지 실전 팁으로 토큰 낭비 방지 가능

### 주요 내용

**토큰 소진의 구조적 원리**
- AI는 카카오톡과 달리 매번 전체 대화를 처음부터 끝까지 다시 읽음. 10번째 프롬프트 요청 시 이전 9개의 요청과 응답을 모두 재처리하므로 대화가 길어질수록 같은 질문에도 비용이 증가
- 컨텍스트 윈도우(한 번에 처리 가능한 토큰 총량)는 Claude 모델이 20만 토큰이며, Sonnet과 Opus는 100만 토큰 베타 지원. 하지만 코드베이스 탐색과 파일 읽기로 금방 소진됨
- 컨텍스트 관리를 안 하면 컨텍스트 롯(썩음) 발생 → 토큰 낭비 → AI 환각(할루시네이션) → 재작업으로 토큰 재소진의 악순환 반복

**플랜별 사용량 및 전략 (Anthropic 공식 발표 기준)**
- Pro 플랜: Sonnet 주당 40-80시간, Opus는 매우 제한적
- Max $100 플랜: Sonnet 주당 140-280시간, Opus 주당 15-35시간
- Max $200 플랜: Sonnet 주당 240-480시간, Opus 주당 20-40시간
- Pro 플랜은 Sonnet 위주 사용하고 Opus는 정말 필요할 때만 사용해야 함. Max 플랜도 모니터링 필수

**모델별 특징 및 선택 기준**
- Opus: 시니어 개발자급, 가장 똑똑하지만 토큰 4-5배 소모. 복잡한 설계나 어려운 문제 해결용
- Sonnet: 중급 개발자급, 균형 잡힌 모델. 일반 코딩, 파일 수정, 기능 구현에 충분
- Haiku: 주니어 개발자급, 가장 빠르고 저렴. 간단한 질문이나 파일 검색용

**실전 설정 방법 (6가지 팁)**
1. **모델 고정**: `/model` 명령어로 현재 모델 확인, settings.json에서 기본 모델을 Sonnet으로 설정하면 매번 자동 적용
2. **Opusplan 활용**: `/model opusplan` 설정 시 계획 단계는 Opus, 실행 단계는 자동으로 Sonnet 전환. Pro 플랜 사용자에게 적합
3. **/clear로 컨텍스트 초기화**: 작업 완료 후 /clear로 메시지 초기화. 사전에 /rename으로 세션 이름 지정하면 /resume으로 복귀 가능
4. **/compact로 대화 압축**: 컨텍스트 윈도우가 가득 찰 때 사용. 중요 내용만 요약하여 유지하고 불필요한 내용 제거
5. **Extended Thinking 제어**: 기본 활성화된 확장된 사고 기능은 최대 3만 토큰 이상 소모. /config로 비활성화하거나 환경 변수로 예산 조절 가능
6. **구체적 프롬프트 작성**: "이 코드를 개선해 줘" → 프로젝트 전체 탐색. "login.js의 로그인 함수에 입력값 검증해 줘" → 해당 파일만 열어 작업. 같은 결과도 토큰 차이 수십 배

**추가 최적화 전략**
- MCP Tool Search: 기본값 auto(10% 초과 시 발동)를 루(항상 활성화)로 설정 권장
- CLAUDE.md 메모리 파일: 공식 문서 권장 500줄 이하 유지. "항상 이렇게 해 줘" 같은 핵심 규칙만 남기고, 가끔 쓰는 상세 지식은 스킬(필요할 때만 로드)로 분리
- 서브에이전트, 훅, 플러그인, 마켓플레이스 등 다양한 컨텍스트 관리 방법 존재
