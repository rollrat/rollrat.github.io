## AI 잘 쓰는 사람은 조용히 설계합니다.(feat.harness engineering)
> 📅 2026-02-18 | ⏱️ 약 6분 | [영상 링크](https://www.youtube.com/watch?v=BssPGKsP60s)

### 핵심 요약
- AI 활용의 패러다임이 **프롬프트 엔지니어링 → 컨텍스트 엔지니어링 → 하니스 엔지니어링**으로 진화했다.
- **하니스(Harness)**는 CLAUDE.md 등 컨텍스트 파일 + MCP 서버 + 스킬 파일 + 에이전트 설정을 모두 합친 AI 환경 전체 설계다.
- 같은 AI 모델이라도 하니스 세팅에 따라 결과가 **10배** 차이 날 수 있다 — "모델이 아니라 하니스가 병목".
- OpenAI가 Codex 에이전트만으로 5개월 만에 **100만 줄 코드, 1500개 PR**을 자동 생성했고, 엔지니어 역할이 "환경을 만드는 것"으로 전환됐다.
- 2025년이 컨텍스트 엔지니어링의 해였다면, **2026년은 하니스 엔지니어링의 해**다.

### 주요 내용

**AI 활용 패러다임의 3단계 진화**
- **프롬프트 엔지니어링** (ChatGPT 초기): 질문을 잘 쓰는 기술. 역할 부여, 단계별 지시, 예시 삽입.
- **컨텍스트 엔지니어링** (2025년): AI에게 "뭘 보여줄지"를 설계하는 기술. Andrej Karpathy(前 테슬라 AI)가 "프롬프트보다 컨텍스트 엔지니어링이 핵심"이라고 했고, 가트너가 프롬프트 엔지니어링 시대의 공식 종료를 선언.
- **하니스 엔지니어링** (2026년): 컨텍스트 파일 + MCP + 스킬 + 에이전트 설정을 포함한 AI 에이전트 전체 환경 설계. 컨텍스트 엔지니어링은 하니스의 일부다.

**하니스(Harness)의 4가지 구성 요소**
1. **CLAUDE.md 등 컨텍스트 파일**: 프로젝트 구조, 규칙, 패턴을 AI에게 명시
2. **MCP 서버 설정**: AI가 사용할 외부 도구 연결 (브라우저 자동화, 문서 검색, 디자인 도구 등). 단, 많을수록 좋은 게 아니며 토큰 관리가 중요.
3. **스킬 파일**: 특정 작업의 전문 지식을 파일로 정리 (예: "영상 편집 시 이 워크플로우로 해", "코드 리뷰는 이 기준으로 해")
4. **에이전트 설정**: 유저가 커스터마이징한 전문가 역할 설정

**주방 비유로 이해하는 하니스**
- 컨텍스트 엔지니어링 = 요리사에게 좋은 재료를 골라주는 것
- MCP 설정 = 수산시장·정육점·농장과 직통 연결하는 어댑터
- 스킬 파일 = 레시피를 정리해 두는 것
- 에이전트 설정 = 셰프를 만드는 것
- **하니스 엔지니어링 = 주방 전체를 설계하는 것**

아무리 좋은 재료(모델)를 줘도 주방(하니스)이 엉망이면 좋은 요리(결과)가 나올 수 없다.

**OpenAI Codex 실험 사례**
- 2025년 8월부터 Codex AI 에이전트만으로 내부 제품 개발 시작
- 결과: 수동 작성 코드 **0줄**, 5개월 만에 **100만 줄** 코드 생성, **1500개 PR** 머지, 엔지니어 1명이 하루 평균 **3.5개** 작업 처리
- **처음에 느렸던 이유**: 모델 무능이 아닌 하니스 세팅 미흡 (환경 설정 부족, 도구 연결 어설픔, 에러 복구 로직 없음)
- 하니스를 하나씩 잡아나가자 성과 폭발적 증가
- OpenAI 내부: "엔지니어링 팀의 주된 역할이 에이전트가 유용한 일을 할 수 있게 만드는 것이 됐다"

**지금 당장 실천할 3가지**
1. **CLAUDE.md 컨텍스트 파일 제대로 작성**: 프로젝트 구조·규칙·패턴을 명확히 기재
2. **MCP 서버 세팅**: AI가 외부 도구를 쓸 수 있게 연결 (단, 토큰 최적화 필수)
3. **스킬 파일 제작**: 자주 하는 작업의 워크플로우와 기준을 파일화

**하니스가 장기 경쟁력인 이유**
모델 성능은 몇 주 만에 경쟁사가 따라잡을 수 있다. 그러나 하니스(도구 연결, 에러 처리, 승인 흐름, 방법론)는 시간을 들여 쌓아야 하므로 쉽게 복제되지 않는다. 지금 하니스에 투자하는 회사·개인이 나중에 진짜 경쟁 우위를 갖게 된다.

### Q&A

**Q1. 하니스 엔지니어링과 컨텍스트 엔지니어링은 어떻게 다른가요?**
컨텍스트 엔지니어링은 AI에게 어떤 정보(컨텍스트)를 제공할지 설계하는 기술로, 하니스 엔지니어링의 한 부분이다. 하니스 엔지니어링은 그보다 훨씬 넓은 개념으로, 컨텍스트 파일(CLAUDE.md)뿐 아니라 MCP 서버 연결, 스킬 파일, 에이전트 설정까지 AI 에이전트를 둘러싼 전체 환경을 설계하는 것이다. 쉽게 말해 컨텍스트 엔지니어링이 "재료 선택"이라면, 하니스 엔지니어링은 "주방 전체 설계"에 해당한다.

**Q2. MCP 서버를 많이 연결할수록 AI 성능이 좋아지나요?**
그렇지 않다. 영상에서 "MCP를 많이 주면 줄수록 좋지 않다"고 명확히 언급했다. MCP 도구가 많아질수록 AI의 컨텍스트 토큰이 많이 소모되어 오히려 성능이 저하될 수 있다. 필요한 도구만 선별적으로 연결하고, 토큰이 과도하게 사용되지 않도록 다양한 최적화 기법을 적용해야 한다.

**Q3. 개인도 하니스 엔지니어링을 적용할 수 있나요?**
개인에게도 동일하게 적용된다. AI 도구를 단순히 사용할 줄 아는 것은 이제 기본이며, 차별화되는 역량은 AI를 얼마나 잘 세팅하느냐다. 개인도 자신의 업무에 맞게 CLAUDE.md를 작성하고, 자주 수행하는 작업을 스킬 파일로 만들어두면 AI가 그 분야의 전문가처럼 일할 수 있다. 채널 운영자는 자신의 하니스 코드가 담긴 GitHub 주소를 구독자 이벤트로 공유하고 있다.
