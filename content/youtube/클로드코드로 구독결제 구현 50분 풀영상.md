## 클로드코드로 구독결제 구현 50분 풀영상
> 📅 2026-02-16 | ⏱️ 49분 | [영상 링크](https://www.youtube.com/watch?v=yb-khA8M8Ow)

### 핵심 요약
- 루비온 레일즈(Rails) + 클로드 코드(Claude Opus 4.5)를 이용해 구독 결제 시스템을 처음부터 실시간으로 구현하는 풀영상으로, MCP나 커스텀 설정 없이 순정 모드로 진행한다.
- 구독 결제는 단순 자동결제가 아니라 취소 유예(만료일까지 서비스 유지), 취소 철회, 플랜 업/다운그레이드 등 복잡한 상태 관리가 필요하며, 이를 프롬프트 작성 전에 깊이 기획해야 한다.
- 결제 연동과 구독 로직은 분리해서 단계적으로 구현하는 것이 디버깅 효율을 높이는 핵심 전략이다.
- 자동 갱신 결제는 Solid Queue 기반 백그라운드 잡으로 처리하며, 잡은 매일/매시간 실행하되 내부에서 만료 조건을 필터링하는 방식이 올바른 설계다.
- 실서비스 전환은 토스페이먼츠 라이브 API 키 교체만으로 완료되며, 개발 환경에서는 구독 주기를 5분으로 단축해 자동갱신 동작을 빠르게 검증할 수 있다.

### 주요 내용

#### 1. 프로젝트 세팅 및 회원가입 구현
Rails 8.1 프로젝트를 Tailwind CSS 기반으로 생성하고 이메일/비밀번호 기반 회원가입·로그인을 구현한다. 클로드 코드 버전 2.0.55, 모델은 Claude Opus 4.5 사용(Max 요금제 기준). gem 추가 후 서버 재시작이 필요한 경우를 실수와 함께 보여주며, 프로 요금제 사용자는 Claude Sonnet 4.5를 사용하면 된다.

#### 2. 구독 플랜 구조 설계 (결제 없이 구조 먼저)
Free / Basic(100원) / Pro(200원) 3단계 플랜을 정의하고, 플랜 테이블·구독 테이블·사용자 테이블 확장을 구현한다. 결제 연동 이전에 구독 로직만 먼저 격리해서 구현하는 것이 핵심 전략이며, 여러 이슈를 동시에 구현하면 문제 원인 파악이 어려워진다.

#### 3. 구독 취소 정책 구현 (즉시 취소 → 만료일 후 전환)
초기 구현은 취소 즉시 Free 전환이었으나, `pending_cancellation` 상태와 `cancelled_at` 필드를 추가해 만료일까지 서비스 유지 후 Free 전환하도록 수정한다. 취소 철회는 `cancelled_at`을 `nil`로 초기화하는 것만으로 구현 가능하다. 사용자에게는 "구독 취소가 예정되었습니다. N월 N일까지 이용 가능합니다"라는 메시지가 표시된다.

#### 4. 토스페이먼츠 실결제 연동
Faraday gem으로 API 호출 레이어를 구성하고, 빌링키 발급 → 자동결제 → 결제 취소 흐름을 구현한다. MCP 문서 연동 없이도 클로드가 토스페이먼츠 API 경로와 파라미터를 정확히 작성했으며, JavaScript 위젯 방식 오류 발생 후 API 방식(브랜드페이)으로 전환해 카드 등록 팝업을 정상 구현한다. 자바스크립트 콘솔 오류는 개발자 도구 콘솔 탭에서 확인 후 그대로 붙여넣으면 클로드가 수정한다.

#### 5. 관리자 페이지 구현
`/admin` 경로에 관리자 대시보드를 생성하고, Rails 콘솔에서 `user.update(admin: true)`로 권한을 부여한다. 사용자 관리, 구독 관리, 결제 내역 조회 기능이 자동 생성되었으며, 테스트 편의를 위한 "즉시 취소(Force Cancel)" 기능을 추가 요청으로 구현한다. 관리자 기능은 프롬프트 한 줄로 CRUD 전체가 만족스럽게 생성된다.

#### 6. 자동 갱신 결제 잡(Job) 및 스케줄링
`RenewSubscriptionJob`(매시간 실행)과 `ExpireSubscriptionJob`(매일 새벽 2시)을 Solid Queue 기반으로 구현하고 `config/recurring.yml`에 스케줄을 등록한다. 잡이 월 1회가 아닌 매시간 돌아야 하는 이유는 사용자마다 결제일이 다르기 때문이며, 잡 내부에서 당일 만료 조건을 필터링한다. 이 영상에서는 개발 환경에서 구독 주기를 5분으로 단축 설정해 7분 후 자동결제 내역 생성을 영상에서 실시간 확인한다.

#### 7. 디자인 개선 및 실서비스 전환 안내
기능 구현 완료 후 "shadcn 스타일, 메인 컬러 초록, 그라데이션" 프롬프트만으로 구독 플랜 페이지 디자인을 1~2분 내에 개선한다. 디자인은 핵심 기능 구현이 완료된 후에 작업하는 것이 권장 순서이며, 이후 추가 기능 구현 시 AI가 기존 디자인 컨셉을 참고해 일관성을 유지한다. 실서비스 전환은 토스페이먼츠 이용 신청 → 심사 승인 → 라이브 키 교체만으로 완료된다.

### Q&A

**Q1. 구독 취소 시 즉시 해지가 아닌 만료일까지 유지하는 로직은 어떻게 구현하나요?**
`subscriptions` 테이블에 `cancelled_at` 컬럼을 추가해 취소 신청 시점을 저장하고, 상태를 `pending_cancellation`으로 관리한다. 만료일(`expires_at`)이 지나는 시점에 백그라운드 잡이 이 조건을 감지해 Free 플랜으로 전환한다. 취소 철회는 `cancelled_at`을 `nil`로 초기화하기만 하면 되므로 구현이 매우 단순하다. 이 패턴은 대부분의 구독 서비스가 사용하는 표준 정책으로, 사용자에게는 만료일을 포함한 안내 메시지가 표시된다.

**Q2. 자동 갱신 결제 잡은 왜 월 1회가 아니라 매일 또는 매시간 실행해야 하나요?**
사용자마다 결제일이 다르기 때문에 잡 자체는 매일 돌아야 한다. 예를 들어 잡을 매월 5일에만 실행하면 10일에 가입한 사용자는 거의 25일이 지나서야 갱신 처리된다. 대신 잡 내부에서 "오늘이 만료일인 구독"만 필터링해 처리하므로 불필요한 중복 결제는 발생하지 않는다. 이 영상에서는 개발 환경에서 주기를 5분으로 단축해 7분 후 자동결제 내역이 생성되는 것을 실시간으로 확인했다.

**Q3. 토스페이먼츠 테스트 환경에서 실서비스로 전환할 때 어떤 작업이 필요한가요?**
코드 변경은 거의 필요 없으며, 환경변수에 설정된 API 키 값만 테스트 키에서 라이브 키로 교체하면 된다. 토스페이먼츠 개발자센터에서 이용 신청 후 심사 승인을 받으면 라이브 키가 발급된다. 사업자 등록증이 없는 경우 토스페이먼츠 가입 페이지에서 간편하게 사업자 등록 신청도 함께 진행할 수 있다. 개발 환경과 프로덕션 환경의 환경변수를 분리해 관리하면 테스트 키가 실서버에 적용되는 실수를 방지할 수 있다.
